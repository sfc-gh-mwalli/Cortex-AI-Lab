The Narrative

Healthcare organizations managing value-based care contracts — ACOs, bundled payments, quality bonus programs — must answer two types of questions at scale:

  1. Analytical questions over structured data — "Which patient populations are driving the highest total cost of care? Where are we seeing avoidable ED utilization?" These answers live in claims, encounters, and clinical measures.
  2. Clinical questions over unstructured data — "What does this patient's care history show about gaps in their chronic disease management?" These answers live in clinical notes and care plans.

Today you will build the core components of a VBC care intelligence platform that bridges both.

In Snowflake, your context tells the platform what role, warehouse, database, and schema to use for everything you do. It's always visible as a status bar at the bottom of the Snowsight editor — for example:

Module 2 · Step 7

Cortex Search Overview

⏱ ~5 min

What Is Cortex Search?

Cortex Search is Snowflake's fully managed search service for unstructured text. Point it at any text column in a Snowflake table and it automatically indexes the content, generates vector embeddings (a numerical fingerprint of each piece of text that captures its meaning, not just its words), and serves search queries — with no infrastructure to manage, no model to train, and no pipeline to build.

Under the hood it uses hybrid search: a combination of those meaning-based embeddings and traditional keyword scoring (which handles exact word and phrase matching). Together these outperform either method alone, especially for domain-specific content like clinical documentation.

Semantic Search — What That Means

Traditional keyword search finds documents containing the exact words you typed. Semantic search finds documents that mean what you're asking, even if the words don't match.

In a clinical context this matters enormously. A care manager searching for "patient with poorly controlled blood sugar missing labs" should surface notes that mention HbA1c, A1C, glycemic index, or endocrinology follow-up — none of which contain the search phrase. Cortex Search handles this automatically because it understands the meaning behind words, not just the words themselves.

What We're Doing in This Lab

We have a dataset of 1,500 AI-generated clinical notes in SOAP format (Subjective, Objective, Assessment, Plan) — synthetic patient records produced from the Synthea dataset. These notes are in a CSV file called Clinical_Notes_RAW.csv.

In this module we will:

  1. Load Clinical_Notes_RAW.csv into a Snowflake table in VBC_LAB.CARE_ANALYTICS
  2. Create a Cortex Search Service on top of that table — one SQL command
  3. Query the service to verify it works
🤖
Why this matters for Module 3: The agent we build in Module 3 will have two tools available to it — the semantic view from Module 1 (structured VBC analytics via Cortex Analyst) and the Cortex Search service from this module (unstructured clinical notes). The agent decides which tool to use based on the question. Structured metrics questions route to Analyst; narrative patient history questions route to Search.

Other Example Uses for Cortex Search

  • Searching provider directory and formulary documentation
  • Surfacing relevant clinical protocols for specific diagnoses
  • Finding prior authorization documentation for specific medications
  • Identifying patients with similar care gaps across a large population
  • Making contracts, policies, or compliance documents queryable by plain language

If something goes wrong, click the ▾ chevron next to the Connected button to access kernel controls:

  • Restart kernel — Clears all variables but keeps packages. Use this if a cell gets stuck or produces an unexpected error mid-run.
  • Shut down kernel — Fully stops the runtime. Use this for a completely clean start; you'll need to reconnect afterward.

What the Notebook Does

  1. Setup & Stage — Sets the session context to VBC_LAB.CARE_ANALYTICS, creates an internal stage, and copies the CSV from your workspace onto it. A preview shows raw rows read directly from stage — no table exists yet.
  2. AI_COMPLETE — Data quality scan (~1–2 min) — An LLM scans all 1,500 notes for PII hidden in the note text (SSNs, phone numbers, email addresses, physical addresses) and flags any mismatches between the structured metadata and what the note actually says. Only rows with issues are returned.
  3. AI_REDACT — Preview — For the flagged rows, shows exactly what PII was found and what placeholder it will be replaced with (e.g. [NATIONAL_ID], [EMAIL], [ADDRESS]) before anything is written.
  4. AI_REDACT + Load (~1–2 min) — Creates the final CLINICAL_NOTES table in a single pass. Flagged rows have PII replaced in-flight; clean rows pass through unchanged. The raw PII never touches a permanent table.
  5. Create Cortex Search Service — Creates CLINICAL_NOTES_SEARCH on the clean table and runs a semantic test query to confirm it's working.
✅
Checkpoint: The final cell searches for "mucoviscidosis with pulmonary exacerbation" — a clinical term that doesn't appear verbatim in any note. If the results come back about Cystic Fibrosis (CF) patients, semantic search is working correctly.

Once the notebook finishes, free up the compute it was using before moving on: click the ▾ chevron next to the Connected button and select Shut down kernel, then close the notebook tab.

Create Semantic View

⏱ ~10 min
What is a Semantic View?

A semantic view is a native Snowflake object — defined using SQL DDL and stored at the schema level — that organizes business metrics, dimension relationships, and domain logic directly in your database. Rather than embedding business logic in every query or BI tool, you define it once in the semantic view and it becomes the authoritative source for how your data should be interpreted.

Semantic views power Cortex Analyst, Snowflake's natural language query engine. Once a semantic view is in place, users can ask plain-language questions and get accurate SQL-backed answers — because the semantic layer already knows what the data means.

2. Add Metrics and Dimensions

Beyond what Autopilot generates, we need two types of additions for this lab:

  • Metrics are named calculations — business measures defined once in the semantic view so every query uses the same logic. For example, Average Cost per Encounter is AVG(total_claim_cost). Without a metric, Cortex Analyst has to guess the formula each time. You can expand Metrics in the Suggestions panel to see what Autopilot identified — but for this lab we'll use a specific set of VBC metrics and dimensions, added via the SQL script below.
  • Dimensions are attributes used to slice and filter data. Most dimensions come directly from a column, but expression-based dimensions are derived from logic. For example, Patient Income Band isn't a column in the data — it's a CASE expression that buckets the INCOME value into ranges like <30k, 30-60k, etc. These let Cortex Analyst answer questions like "show cost by income band" without any transformation in the query.
  1. Copy the SQL using the button below.
  2. In your snowday workspace, click the + button to the right of the rightmost open tab and select SQL file.
  3. Rename the new file: click the ··· menu on the tab and choose Rename, then name it create_vbc_analytics_sv_updated.sql.
  4. Paste the SQL into the file and run it with ▶ Run.

The script is a CREATE OR ALTER SEMANTIC VIEW — it adds the new dimensions and metrics to your existing VBC_ANALYTICS_SV in place. CREATE OR ALTER is an idempotent DDL command that creates the object if it doesn't exist or updates it to match the new definition if it does — safe to run multiple times without side effects (docs). Module 3 · Cortex Agents

Why Agents?

⏱ ~30 minutes total
⏱ 3 min — Business Context

You now have two powerful tools: a semantic search over clinical documentation, and a natural language analytics engine over VBC metrics. But real care management questions don't fit neatly into one category:

💬
"This patient had three ED visits this year — what's driving it, and does their care plan address it?"

That requires both their clinical notes AND their utilization data. That's what a Cortex Agent does — it reasons across both tools and synthesizes one answer.

Key Concepts

  • Tool orchestration — The agent is given a set of tools (a search service and a semantic view) and decides which to use per question. No if/else routing logic to write.
  • Multi-tool synthesis — For complex questions, the agent calls multiple tools and synthesizes a single coherent answer.
  • Guardrails — Agents are scoped to their tools. Questions outside that scope are declined gracefully.
  • Auditability — Every tool call and reasoning step can be logged — critical in a regulated environment like healthcare.

VBC Use Cases

  • Care manager co-pilot — surface patient risk from notes + utilization trends in one answer
  • Quality analyst assistant — combine protocol documentation with HEDIS measure data
  • Population health dashboard back-end — answer complex cohort questions automatically
  • Prior auth triage — match policy documentation with patient claims history

Step 1 — Create the Agent with Cortex Code

Open a new Cortex Code chat in Snowsight and paste the prompt below. Cortex Code will create the agent, configure both tools, and set the orchestration and response instructions.

💡
Start a fresh chat — don't paste this into an existing conversation. A clean context helps Cortex Code focus entirely on the agent creation task.
💬 Paste into Cortex Code

Execute the following directly:

Create a Cortex Agent in VBC_LAB.CARE_ANALYTICS with the following configuration:

Name: VBCCAREAGENT
Display name: VBC_CARE_AGENT

Add two tools:
1. A Cortex Analyst tool using semantic view VBC_LAB.CARE_ANALYTICS.VBC_ANALYTICS_SV — for structured questions about costs, encounters, utilization, and VBC metrics
2. A Cortex Search tool using service VBC_LAB.CARE_ANALYTICS.CLINICAL_NOTES_SEARCH — for searching clinical notes and patient narratives

Orchestration instructions:
You are VBC Care Agent, an intelligence assistant for care managers and program analysts working with value-based care data. Your scope covers two data sources: structured VBC metrics and unstructured clinical notes. Use the VBC Analytics tool for questions about costs, utilization rates, encounter volumes, quality measures, and population trends. Use the Clinical Notes tool for questions about individual patient notes, care plan documentation, clinical narratives, or care gaps documented by providers. For complex questions that require both structured data and clinical context, use both tools and synthesize the results into one answer. Politely decline questions that fall outside these two data sources.

Response instructions:
Always cite which tool or data source was used to answer. Present numbers clearly with appropriate context. Lead with the direct answer, then provide supporting detail. Do not make clinical recommendations — present data and documentation only.

CoWork setup:
After creating the agent, register it with Snowflake CoWork so it can be previewed and used:
1. Create a Snowflake Intelligence object if one does not already exist:
CREATE SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT;
2. Add the agent to the Intelligence object:
ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT ADD AGENT VBC_LAB.CARE_ANALYTICS.VBCCAREAGENT;
3. Grant usage on the Intelligence object to the appropriate role:
GRANT USAGE ON SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT TO ROLE ACCOUNTADMIN;

💬 Snowflake CoWork — Multi-Tool Question

We're seeing high avoidable ED utilization in our diabetic population. What do the clinical notes say about care plan adherence for these patients, and what does the data show about their encounter patterns?

⭐
This is what makes agents different from a search bar or a dashboard. The agent:

1. Breaks the question into two sub-questions
2. Searches ClinicalNotes → retrieves notes about diabetes care plan adherence
3. Queries VBCAnalytics → pulls encounter patterns for diabetic patients
4. Synthesizes both results into one coherent answer — citing both sources

No if/else routing logic to write. No joins across systems. The agent does the reasoning.

Wrap-Up

Key Takeaways & Next Steps

⏱ ~5 min

What You Built Today

  • 📊Cortex Analyst + Semantic View — democratizes VBC analytics. Program managers ask in plain English; governance and consistent definitions stay intact.
  • 🛡️Cortex AI Functions — in the loading notebook, AI_COMPLETE scanned 1,500 clinical notes for hidden PII and data quality issues, and AI_REDACT stripped that PII in-flight before the data ever landed in a table. AI ran directly in SQL, inside the pipeline.
  • 🔍Cortex Search — makes clinical documentation conversationally discoverable. Care managers find relevant patient history using natural language, in seconds.
  • 🤖Cortex Agent — bridges clinical notes and structured data. The most complex care management questions can now be answered automatically, across both sources.
  • 🧠Snowflake CoWork (formerly Snowflake Intelligence) — surfaces the agent as a polished conversational UI for business users, no SQL required.
  • ❄️Everything runs inside Snowflake — no data egress, no separate AI infrastructure, no new security perimeter. Critical for HIPAA compliance.
